How it works

The gradient is not painted on the page background at all. It lives on its own position: fixed element behind the content — that's the part iOS handles fine. What iOS breaks is background-attachment: fixed, so we simply never use it.

Two extra rules make the black bar impossible. The gradient fades to fully transparent before its own edge, and the layer overdraws past the bottom of the viewport using 100lvh — the "largest viewport" unit, meaning the size when Safari's URL bar is collapsed. So when the URL bar expands or collapses, there is no edge to expose.

.glow-fixed {
  position: fixed;          /* NOT background-attachment */
  left: -12%; right: -12%;
  bottom: -18lvh;           /* overdraw past the edge */
  height: 90lvh;            /* sized to largest viewport */
  z-index: 0;
  pointer-events: none;
  background: radial-gradient(80% 68% at 10% 98%,
    rgba(43,92,255,.50) 0%,
    rgba(32,64,200,.24) 36%,
    rgba(0,0,0,0)       72%);  /* fades out — no edge */
}
body { background: #000; }   /* matches gradient end color */

The bottom nav uses backdrop-filter: blur(), so whatever scrolls underneath it — cards, gradient, footer — looks intentional instead of clipped.

What I've been talking about

  • The bug we're seeing: the glow strip rides the bottom of the viewport with a hard edge, and jumps when the iOS URL bar resizes. Tap Broken (now) above and scroll — that's the current dev build behavior.
  • Why "fixed everywhere except iOS" isn't needed: the iOS bug only affects background-attachment: fixed. A fixed-position element is fully supported, so one implementation works on every platform. No fork.
  • Julien's transparent-edge idea is in here too: the gradient terminates in transparent, so even if sizing were off, nothing can cut off visibly. The two ideas combine — they aren't alternatives.
  • Option: blue footer. Tap Blue footer above — the footer and copyright bar take the gradient color, so the page bottom isn't black at all and the gradient has nowhere to "end". Design call, both work.
  • Horizontal gradients on mobile: same rule applies — as long as every gradient ends in transparent over the page's base color, it can never cut weirdly at any viewport size.
